I ran a small study to find out whether "vibe-coded" repos are worse code. I compared 46 pairs of Python repos on GitHub, half written with AI tools and half written traditionally, matched by size, age, and popularity. I couldn't tell them apart.

The setup: I found public Python repos whose authors openly used AI tools, either through bot commits (Claude, Copilot, Cursor) or README declarations. Each got paired with a traditionally-written repo of similar size, age, and popularity. Then I measured both sides blind: function complexity, function length, comment share, documentation mistakes. Only after all numbers were collected did I reveal which repos were the AI ones.

Every statistical test came back inconclusive. Across five measures, though, the AI-assisted repos leaned slightly cleaner:

- Fewer overly complicated functions (4.6% vs 6.5%)
- Lower average function complexity
- Shorter functions
- Fewer documentation mistakes per 1,000 lines
- A higher share of comments in the code

None of these gaps prove anything at 46 pairs. Still, they all point one way: the vibe-coded repos weren't sloppier. If anything, they trended toward smaller, simpler, better-commented functions.

Honest caveats before anyone runs with this.

This is a pilot. Enough to see shapes, not enough to claim findings.

These are repos whose authors chose to announce their AI use and publish the result. That selects for people who cared enough to ship something, not the abandoned projects nobody uploaded.

The measures don't check correctness. A repo can look clean and still compute the wrong thing.

Matching wasn't perfect either. I only kept properly licensed repos, which cut 40% of my first batch.

Next: expand the sample, add checks that test whether the code actually works, write it up properly. Every script and raw number is public at github.com/adamafzainizam/vibe-code-quality-study

Full disclosure: I used AI tools to build the pipeline and draft this post. Using AI to study AI felt appropriately on-theme.

My take: coding is one of the few places where AI use should be encouraged, because it's verifiable. The code runs or it doesn't. Tests pass or they fail. But encouraged isn't the same as blind. Vibe-code without learning anything and you ship holes you can't see and can't fix at 2am. You still need to review, test, understand what you ship. Software is also one of the few domains where AI takes the repetitive work and leaves humans the interesting parts.

One line I keep coming back to: I want AI to do my laundry so I can make art. Not AI making art so I can do laundry.

After all the talk about AI slop flooding GitHub, the difference between published vibe-coded Python and traditional counterparts is roughly nothing. Maybe the question isn't whether AI code is worse. Maybe it's why we expected it.
